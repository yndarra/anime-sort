engine — движок конвейера
=========================

Цепочка запуска (консолей нет — у main.py главное окно gui\main_window.py):
    start.vbs -> main.py -> batch.py (одна на конфиг из run) -> dataset.py (на каждую папку) -> run.py

main.py       главное окно anime-sort (окно — главный поток, диспетчер — фоновый): проверяет конфиги
              (ошибки — красным в журнале окна и в logs\config_check.txt,
              окно не закрывается), делает снимок конфигов в logs\config-snapshots\<время> (пачки читают его),
              запускает правильные пачки; сломанные ждут исправления и запускаются после сохранения файла.
              Следит за live.json, показывает журналы пачек (копия — logs\console.log). Всё запущенное
              привязано к главному окну (job object Windows): закрыли его — остановились пачки, конвейеры и окна.
              --check — только проверка.
batch.py      пачка одного конфига: папки из folders по порядку; при падении набора — до 2 перезапусков,
              наборы с оставшимися ошибками повторяются в конце; при исчерпании баланса ключа — стоп.
              Журнал: logs\batch_<name>.log. Одна пачка на конфиг (именованный мьютекс Windows).
dataset.py    один набор: копирует source\dataN в results\test-dataN\in, открывает окно набора,
              обновляет каталог tools\ani\ani.txt, запускает run.py, по успеху пишет итоговый снапшот
              out\status_snapshot.json и удаляет work\. Завершённый набор пропускает, если этапы
              конфига не менялись; иначе открывает его снова со всем сохранённым состоянием.
run.py        конвейер набора: этапы конфига по порядку (модули stages\<type>.py).
              Коды выхода: 0 готово, 3 кончился баланс, 4 ошибка в конфиге, 5 остались файлы с ошибками.

config.py     чтение и подробная проверка configs\*.json и providers\*\provider.json
jsonconf.py   чтение JSON с номерами строк, понятные сообщения о синтаксических ошибках, "//"-комментарии
live.py       configs\live.json — параметры на ходу; главное окно публикует проверенные значения в
              logs\live_effective.json, конвейеры читают только их
core.py       набор: состояние файлов (work\chunk_XXXX\_state.json), лог событий для окна,
              папки результатов (нумерация по конфигу, переименование при смене этапов), «0. ALL», «Other»
client.py     запросы к моделям через провайдера, кэш ответов, повторы при сбоях сети и rate limit
tagger.py     локальные теггеры WD-14 и Camie (onnx) и индекс персонажей
ani_catalog.py каталог частых тайтлов/персонажей (tools\ani\ani.txt) для json_meta
nowmi.py      обход падения 0xC000070A: отключает WMI-запрос модуля platform до импорта onnxruntime
winproc.py    процессы Windows: жив ли процесс, остановка, job object, привязка к ядрам, цвета консоли

Ядра: конвейер привязан к первым (всего - free_cores) ядрам (live.json, по умолчанию 2 свободных, меняется на ходу),
одинаково во всех пачках, и onnxruntime в tagger.py получает столько же потоков — даже несколько
параллельных WD-14/Camie не займут свободные ядра.
Нехватка памяти: файл не считается ошибкой — пауза и повтор того же файла (live.json); нативное
падение процесса из-за памяти — пачка ждёт 2 минуты и перезапускает набор, не тратя попыток.
Пауза: logs\control.json набора ({"paused": true}) — конвейер ждёт перед следующим файлом.
logs\pids.json набора — какие процессы над ним работают (для кнопок окна).
Битые файлы (core.py: mark_broken): не открывается как картинка; этап не прошёл файл в broken_after_runs
запусках; процесс падал на файле broken_after_crashes раз — logs\current.json (над каким файлом работает
run.py) и logs\crashes.json (падения, их считает dataset.py). Список — out\broken.txt набора.

ANIME_SORT_CONFIGS — откуда читать config.json/configN.json (main.py ставит пачкам папку снимка);
ANIME_SORT_LIVE — путь к live.json (для проверок на тестовых данных).
